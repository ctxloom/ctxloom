ctxloom exposes a small set of tools for retrieving context during a session: search and load fragments, commands, and prior session history. Agent delegation rides here too: agent_run launches a configured ctxloom agent as a child session with its definition fully honored (composed profiles, engine, runtime, permissions), and agent_send/agent_recv are the message bus between coordinator and children (children address only "parent"). All ctxloom management — creating or editing bundles/profiles/fragments/commands, pulling remotes, reviewing/accepting/rejecting remote content, trusting a publisher's signing key, holding bundles at a pin, applying hooks — is done with the ctxloom CLI via your shell (e.g. `ctxloom review`, `ctxloom signer trust <principal> --key <path>`, `ctxloom deps pull`), not through tools here. Task tracking (task_list, task_add, task_set_status, task_edit) is served by the separate `taskloom` MCP server; the same store is scriptable via the `taskloom` CLI.
