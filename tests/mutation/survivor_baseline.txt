# THE SURVIVOR RATCHET. Each row is the survivor count one package is known to
# produce under gomutants, measured whole (`just test-mutation-ratchet PKG`).
# That recipe fails when the package measures MORE survivors than its row.
#
# It does not fail on the counts already recorded: those are tracked debt, and
# a gate that refused them would simply never be run. What it refuses is a
# change that leaves more mechanisms unverified than it found. The project's
# efficacy threshold is still printed; for a ratcheted package it is not the
# verdict.
#
# A survivor is a mutant nothing verified: LIVED (a test ran and did not
# notice) plus NOT COVERED (no test ran the line). The ratchet keys on that
# COUNT, not on the score: code added with good tests raises the score while
# leaving more mechanisms unverified, and the count cannot be moved that way.
# TOTAL is recorded beside it only so a failure can say whether the extra
# survivors arrived with a bigger mutant set; nothing is gated on TOTAL.
#
# TARGET is the package's module-relative directory.
#
# PROVENANCE says what licenses the number:
#   measured  a run of this gate against this repository wrote it.
#   stale     known NOT to describe HEAD — an UPPER BOUND, so it still catches
#             a regression, and the next real run must lower it.
#   unknown   no number exists (TOTAL and SURVIVED are "-"). The gate reports
#             what it measures and calls it neither a pass nor a failure.
#
# Record the row a run measured:
#   CTXLOOM_MUTATION_BASELINE=update just test-mutation-ratchet <dir>
#
# A count that goes DOWN is reported, never lowered automatically. Lowering it
# is what keeps the ratchet tracking the debt down instead of banking slack,
# and it belongs in the diff that earned it.
#
# TARGET                                   TOTAL  SURVIVED  PROVENANCE
internal/adapters/isolation                    -         -  unknown
