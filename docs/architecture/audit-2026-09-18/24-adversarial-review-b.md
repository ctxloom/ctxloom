## 1. VERDICT

The shape holds (hexagon, one composite package, one launch value, one verbs layer, one runner as the unit, config owner with generations) and it resolves four of A's refutations outright (config lifecycle, container mail via the mount, one-shot resume ARM, reach-back carried typed). It does not hold as a set of signatures: the engine port cannot compile (three import cycles), the core ring imports three adapters and the proto package on day one, the MCP endpoint is minted per runner process and after the Plan that must name it (violating post-B ruling 4 and B's own "computed once"), Identity never enters `Resolve`, and the reach-back gate it promises to keep green proves the shim it deletes rather than reach-back.

Before it is built: fix R1–R5 as signatures (engine-facing projection instead of `launch.Launch`; core-owned axis/decision types; endpoint minted per harp in `Resolve` and carried on the Launch; `Source.Identity`; a sealed wire form for `Package` with an explicit message-size bound), rework the delegation journeys first (tacky-padding's ruling), and reorder the slices so nothing names a type from a later slice (§5).

## 2. REFUTED (ranked by how much of the design each invalidates)

### R1. The engine port as written does not compile — three import cycles
**Claim (§1.2):** "`Exec(l launch.Launch, presented []present.Presentation) (Exec, error)`" on `engine.Engine`; "`Uncarried map[delivery.Kind]string`" on `engine.Facts`; §1.4 "`Route(pkg composite.Package, facts engine.Facts, decl engine.Declaration, pref Preference)`" and "`Static.Deliver(ctx, plan Plan, decl engine.Declaration, target Target)`" with "`Construct … func(in delivery.Inputs, fs afero.Fs) Approach`"; §1.5 "`Deps.Engines engine.Registry`", "`CellRequest.Engine engine.Engine`", "`Launch.Engine engine.Name`".
**Counterexample:** `engine` → `launch` (Exec's parameter) while `launch` → `engine` (Deps, CellRequest, Launch): cycle. `engine` → `delivery` (`Facts.Uncarried`, `Construct`'s `delivery.Inputs`) while `delivery` → `engine` (`Route`, `Deliver`, `Target.Cell engine.CellKind`): cycle. `engine` → `composite` (`Exports(pkg composite.Package)`) is acyclic, but the rule §1.1 "`engines-import-nothing-above-the-port`: `internal/engines/**` forbids … `composite`" forbids every engine package from importing the type its own `Exports` method must accept — an engine cannot implement the interface without breaking the rule. The package map's edge list (`ENG --> PRES & WIRE & PATHS`) omits all three edges the signatures create.
**Why it breaks:** Go refuses import cycles; nothing below §1.2 can be typed as drawn, and test A (§4.2) imports `launch` from the conformance package, so it does not compile either.
**Smallest change:** the engine sees only engine-owned types. `engine.Kind`, `engine.Inputs` and `engine.Session` (identity, mode, one-shot, permission, model, home roots, prompt, resume ref, presentations — the engine-facing projection of a Launch) live in `engine`; `delivery` imports `engine` (never the reverse); `Exec(s engine.Session, presented []present.Presentation)`; `Exports(items engine.Items)` where `composite` produces `engine.Items` (a projection), so `engines/**` imports `engine` only and the rule stands. This is also what R10 needs.

### R2. The MCP endpoint is minted per runner process, after the Plan that must name it — post-B ruling 4 violated and B's own ordering contradicted
**Claim:** §1.4 "`Plan` … is computed once per launch, pure, and carried on `launch.Launch`"; §1.6 "`Endpoint` … is minted by whoever hosts the endpoint"; §2.2 step 19 "RN→RN: mint the session MCP endpoint (loopback TCP + bearer) → DynamicItem inputs"; slice 9 "the runner passes the endpoint typed into `Route`'s dynamic inputs before `Deliver`".
**Counterexample (code):** `Coordinator.resumeChild` → `runChildViaStartRun(…, runnerEnv(rt.harp, rt.runID, …))` in `internal/core/coord/children.go` spawns a NEW runner process per one-shot turn (00-coordinator-notes confirms the container start per turn). Under B a runner mints the endpoint, so a one-shot child gets a new listener, a new bearer and a rewritten `.mcp.json` every turn. Ruling 4: "minted per SESSION … stable across one-shot turns."
**Counterexample (signatures):** the engine's MCP file is a STATIC item (claude: `mcp-config`); its content must carry the URL and bearer; `Route` runs in `Resolve` (originator) before any runner exists, and `Static.Deliver(ctx, plan, decl, target)` has no parameter through which the runner could supply the endpoint. So either `Route` runs twice (originator for the Plan on the Launch, runner again "before Deliver") or the runner mutates a value the design calls immutable. `Served{Endpoint}` being an OUTPUT of `Dynamic.Serve` is the same shape the review refuted in A (R2), restated.
**Smallest change:** mint the session's MCP `sessions.Endpoint` in `Resolve` (once per harp, keyed by `Identity.Harp`; a resume reuses it), carry it as `Launch.MCP sessions.Endpoint`, have `Route` read it, and have the runner BIND to the given address (`Dynamic.Serve(ctx, plan, ep)` keeps its signature; `ep` is an input, as B already wrote, but it comes from the Launch, not from the runner). Consequence B must state: an in-container loopback endpoint can only be stable across turns if the RUNNER outlives the turn, so the "does not redesign container lifetime" non-goal (§4.3) is no longer optional under ruling 4 — container/runner lifetime = session harp becomes a required slice (see §5).

### R3. `core-imports-only-core` is red on day one
**Claim (§1.1):** "Core packages import only other core packages"; `launch`, `coord`, `composite` are core; `lm/isolation`, `operations`, `signing` are adapters.
**Counterexample (signatures):** `launch.Source.Workspace isolation.WorkspaceAxis`, `Launch.Axes isolation.Axes`, `CellRequest.Image isolation.ImageConfig`, `ContainerCell.Runtime isolation.Runtime`, `StartRunner … (*isolation.RunnerHandle, …)`; `CellRequest.DirtyTree operations.DirtyTreeHandler` and `coord.SpawnRequest.DirtyTreeHandler operations.DirtyTreeHandler` (`DirtyTreeHandler` is declared in `internal/adapters/operations/delegate.go`); `composite.TrustRoot.TrustedForNamespace(key ssh.PublicKey, …) allowedsigners.Decision` (`signing/allowedsigners` is an adapter in B's map).
**Counterexample (code):** B says `coord` core "splits `grpcserver.go`, `runchannel.go`, `runnerlink.go`, `httpserver.go`, `consumer.go`, `controlwire.go` → `coord/grpc`". Counting `agentcoordpb.` references per non-test file today, the files B KEEPS in core still hold about 180: `home.go` 42, `spooldoorbell.go` 19, `artifacts.go` 14, `spooldelivery.go` 8, `control.go` 8, `reports.go` 6, `items.go` 6, `homeartifacts.go` 6, `children.go` 6, `mailkind.go` 3, `harnessspec.go` 3, `checkpoint.go` 2, `coordinator.go` 1 (`ControlInitiatorKind_CONTROL_INITIATOR_KIND_HUMAN` in code, not a comment). `coord` today also imports `operations`, `config`, `isolation`, `transcript`, `shared/agent`. This is A's R10 (protobuf in core) repeated with a smaller list of files.
**Smallest change:** move `Axes`, `WorkspaceAxis`, `Runtime` (the value types, not the runtimes) into `launch` or `engine`; `DirtyTreeHandler` into `launch`; declare `composite.Decision` in core and let `allowedsigners` return it; and size the `coord` split honestly: a `coord/grpc` codec for mail kinds, control initiators, artifact and doorbell frames (~180 sites), with `coord.Home` re-typed on Go values. The layering row is right; the allowlist it needs on day one is the whole of `coord`, and the design should say so.

### R4. Identity never enters `Resolve`; children would be minted twice or lose their identity
**Claim (§1.5–1.6):** "`Resolve(ctx, deps Deps, src Source) (Launch, error)` … refuses a launch with no harp"; "`sessions.Mint` — called by `operations.StartRun` for the originator's own run … and by `coord.Coordinator.AgentRun` for children (before `run.enqueued` is journaled)"; "the coordinator mints `Identity` first and passes it in `Source`-adjacent `Deps`".
**Counterexample:** neither `Source` nor `Deps` has an `Identity` or harp field; `Deps.Sessions sessions.Store // mints the harp` says Resolve mints; test C asserts `require.NotEmpty(t, l.Identity.Harp, "every launch mints a harp")` from `Resolve` alone with a `FailingStore` producing `ErrNoHarp`. So `Resolve` mints. For a child, `AgentRun` has already minted (and journaled `run.enqueued` under that harp) → a second harp per child, or the coordinator's harp is discarded. `CellRequest.Identity sessions.Identity` "names the workspace and the state mounts" — from a value the signature cannot receive.
**Smallest change:** `Source.Identity sessions.Identity` (required; `Resolve` refuses a zero value with `ErrNoHarp`), delete `Deps.Sessions`; `Mint` stays exactly where B's prose puts it. Test C's first assertion moves to the two callers.

### R5. "A `Package` value cannot be constructed outside `Assemble`" is false once it crosses the wire, and the wire has an unstated 4 MiB cliff
**Claim (§1.3):** "How a package proves it was verified: it exists. A `Package` value cannot be constructed outside `Assemble`"; §1.5 "`DecodeLaunch(*pb.Launch) (launch.Launch, error)` lives in the gRPC adapter"; "`Package` crosses the wire".
**Counterexample:** `DecodeLaunch` is in `coord/grpc` (adapter) and must produce a `composite.Package` including its unexported `attestation` from bytes. Either `attestation` becomes exported (any package can then forge a "verified" Package) or `composite` exports a constructor for the adapter — and then a `Package` exists that no `Trust` decided in this process. Post-B ruling 3 (the Package serializes; the local launcher consumes the same form) makes this unavoidable; B's proof-by-existence is gone. Separately: no `MaxRecvMsgSize`/`MaxSendMsgSize` override exists anywhere in the repo (`git grep`), so grpc-go's default 4 MiB receive limit applies to `StartRun{launch}`; the codebase already knows this ceiling — `Coordinator.serveCustom` in `runchannel.go` enforces `relayCapBytes` at 4 MiB for relayed tool results. Measured on this machine: `~/.ctxloom/cache` is 4.8 MiB in total and the largest skills directory is 48 KiB, so today's corpus fits; the design sets no bound (B's own uncertainty 3).
**Smallest change:** the wire form is `composite.Sealed{Bytes, Attestation, Hash}`; `DecodeLaunch` yields a Launch holding a `Sealed`, and only `composite.Open(sealed) (Package, error)` — which re-verifies the attestation hash over the bytes — produces a `Package`. Set `MaxRecvMsgSize` explicitly with a designed bound and promote B's mitigation ("skills cross as verified manifests plus a content-addressed fetch from the session dir mount") from "if measured" to the design for anything above the bound.

And the `@live @delegation` outline has exactly one Examples block, tagged `@claude-code` (host); the `@claude-code @container-rootless @ws-none` row exists only on the `@live @probe-p6-steer-echo` outline. ### R7. Two ownership records on one target when a session's `unsafe-file` delivery and a human `materialize` meet (A's R4, restated)
**Claim (§1.4):** "`Ownership` is the ONE mechanism … a record per target file naming the entries ctxloom currently owns in it"; the same `Static.Deliver` serves "a session (root = the session home, record = the session's) and a human materialize (root = the project root, record = the project's)". Test B constructs `sessionRec, projectRec := delivery.NewOwnershipFixture(fs), delivery.NewOwnershipFixture(fs)`.
**Counterexample (A4 e):** a binding that names `unsafe-file` roots under `ProjectRoot` (§1.4 says this is the only way a session lands there). Its `Target.Ownership` is the SESSION record. `materialize` then delivers the same kinds into the same files with the PROJECT record. `internal/adapters/confpatch/confpatch.go`'s own doc: "Records are keyed by target alone, so two writers sharing a store on one target would each reverse the other's last application on the way in". **Smallest change:** one record per TARGET regardless of writer: entries tagged with a writer id (`session:<harp>` | `project`), `Target` carries the writer id, and reconcile-to-empty removes only that writer's entries. Then "one mechanism" is true.

### R8. Resume after a coordinator restart has no path — `Spawner.Resume` needs a Launch that no longer exists
**Claim (§1.7):** "`Resume(ctx, l launch.Launch, key string) (launch.Launch, error) // native resume key stamped`"; §1.6 deletes "the `persist/runstart.json` handoff"; the coordinator's "run record is a projection (`RunRecord{Harp, RunID, Engine, Label, Profiles, Runtime, …}`)".

### R17. `Kind MCP` routed DYNAMIC conflates channel with route, and `DynamicItem.Payload any` cannot be the typed, parity-tested wire value
**Claim (§1.4):** arm 3 "MCP when the engine has no MCP file but supports MCP by argv → DYNAMIC"; "`type DynamicItem struct{ Kind Kind; Payload any }`"; §1.5 "a reflection test asserts field-set parity".
**Counterexample:** a package MCP server (taskloom's command, a remote's server) cannot be "served on the session's ONE MCP endpoint"; delivered by argv it is a STATIC presentation over the argv channel (`present.Presentation` already models channels). **Smallest change:** `Route` yields only static routes for `MCP` with the channel chosen by `Presentations` (file | argv); `Dynamic` items become a closed set of kinds with typed payloads (`PremiseCatalog []Item[Fragment]`, `LinkMates []LinkGroup`, `Findings []Finding`, `Resources` derived), so `Plan` is a plain value.

### R18. `Trust` outlives the config generation — the same memo-outlives-the-generation shape as this morning's defect
**Claim (§1.3):** "`Trust` … Constructed ONCE per process at the composition root"; the three ports "are read into memory once by `NewTrust`" — including `RetractionRecords` from "remote's lockfile"; §1.8b makes the lockfile part of a `Snapshot` generation.
**Counterexample:** `deps pull` rewrites the lockfile and `Owner.Reload` produces generation N+1, but the process's one `Trust` still holds generation N's retraction records; a spawn after the pull decides with stale retractions. Nothing in the signatures ties `Trust` to a `Snapshot`.
**Smallest change:** `Snapshot.Trust composite.Trust` built per generation by `Sources` (or `Trust` reads retractions through the Snapshot's catalog lazily); `Deps.Trust` then comes from the same Snapshot the launch already captured.

### R19. The coordinator's comparison overstates B (23-comparison-a-vs-b.md)
**Claims:** "B already holds on seven of the review's eleven refutations of A"; "B moves less code to say the same thing"; "Ownership record: B, provisionally"; core purity "untested".
**Counterexample:** by this review — config owner ✓ (R3 held for A, fixed in B); mail to container ✓ today, broken by B's own spool move (R12 iv); depth ✗ (R11); resume ✗ after restart (R8); ownership ✗ (R7); endpoint-as-input ✗ (R2); reach-back proof ✗ (R6); wire value: ruled moot, size and forgery open (R5). Three of seven, not seven. Layout cost (post-B ruling 5, measured by importing packages from `go list`): B's "keep the names" still moves `claude` (5 importers), `mockengine` (1), `lm/engine` (3), `lm/engines` (2), `lm/backends` (8) and splits `coord`/`sessions`/`config`, and breaks the nine path-pinned arch-test files of R13 — a rename into `core/adapters/engines` adds `paths` (32 importers), `shared/agent` (30), `bundles` (10), `config` (8), `trust` (8), `sessions` (8), `profiles` (6), `coord` (4), `spool` (2) on top: roughly 108 more importing packages plus every `docs/architecture/**` path, for no behaviour. So B is cheaper by about a factor of five on import churn, but not free, and the comparison's "no behaviour" column applies to both. Core purity: answered by R3 — `coord` keeps ~180 proto references outside the six files B splits out.

### R20. One value, two fields — small duplications the design introduces
**Claims:** `Launch.Attestation composite.Attestation` beside `Package.attestation` (with `Package.Attestation()`); `Launch.OneShot bool` beside `Identity.OneShot`; `Launch.Mode` beside `Source.Mode` and `Launch.OneShot` beside `Source.OneShot`; the session home in `Cell.Paths.SessionHome` (a `present.Root`) AND in `Launch.Home HomeSpec` ("the session home on both sides"); `coord.Home` (the runner half, 42 proto references) kept in core `coord` while `runner` absorbs `coord/enginehost*.go` — two homes for runner-side logic.
**Why it matters:** the brief's first emphasis is "every value crosses a boundary ONCE"; each pair is a place the two copies can disagree, and the parity test cannot see it.
**Smallest change:** drop `Launch.Attestation` and `Launch.OneShot` (derive); `HomeSpec` holds vars and provisioning only, the path lives in `Cell.Paths`; `coord.Home` moves to `runner` with the enginehost files (the runner half is an adapter).
